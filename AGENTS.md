# earshot-sfx-lite

The 252 sounds of earshot's bank, rendered by id. Same WAV bytes as `earshot sfx render`, without torch, librosa or ffmpeg.
Needs Python 3.10+ with `numpy` and `scipy` (`pip install numpy scipy`). `pip install numba` makes renders much faster
and does not change a single byte.

## Commands (run from the repo root)
- What is there: `python -m sfxlite list` (add `--kind whoosh`, `--kind hit`, `--kind key` or `--category pro_impact`)
- One sound: `python -m sfxlite render whoosh_fast/crisp -o whoosh.wav`
- Aim it at the picture: `--dur 0.8` (exact length), `--apex 0.32` (loudest moment at 0.32 s, whoosh family),
  `--pitch E5` (tonal sounds), `--seed 7` (a new take of the same sound), `--weight 0.5` (6 dB quieter)
- Audit any effect: `python -m sfxlite check my.wav` (clicks, cut tails, clipping, DC, ring, rising pitch glide)
- The whole pack: `python -m sfxlite export sfx/` (one WAV per id, `--kind` / `--category` to narrow it)

## Choosing a sound
- Cuts and slides: `whoosh_fast/*`, `swish/*`, `swipe/*`; reveals: `riser/*` then `pro_impact/*` or `sub_drop/*`
- Buttons and UI: `click/*`, `pro_click/*`, `toggle/*`, `hover_tick/*`, `ui_pop/*`, `pro_pop_in/*`
- Messages: `notify/*`, `mallet/glock` (tune it with `--pitch`)
- Typing on screen: `typing_key/*`, `fit/key/*`
- Every render prints its onset, peak and end time: use the peak time to line the sound up with a frame.

## Notes for the agent
- A render with no `--seed` is the delivered sound itself. Other seeds are new takes with the same character.
- Output is 24-bit PCM WAV at 48 kHz. `--sr 44100` and the other rates need `pip install soxr`.
- `check` reads PCM WAV only (earshot itself reads any format through ffmpeg).
- The sounds are generated by code (the `fit/*` ones are models fitted to CC0 recordings, see docs/CREDITS_FIT.md),
  MIT licensed, safe to ship in an app or a video.
